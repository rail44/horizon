# 常設エージェントの記憶方式 — 外部実績の証拠調査(2026-08-15)

board #36(常設エージェントの記憶モデル)の判断点「集約を書く主体 —
ハーネスかエージェント自身か」の材料。オーナー要望(2026-08-15)により、
既存実装・調査報告から品質の定量実績を収集した。2系統(ハーネス側自動
要約/エージェント自己管理メモリ)を並行リサーチエージェントで調査し、
統合時に一部の一次出典を再検証した。規約: **数値には年代と検証力
([統制]=独立条件間比較 / [査読] / [独立] / [ベンダー]=自己報告 /
[監査] / [未検証])を必ず併記**。手元の先行調査は
`agent-compaction-prior-art-2026-07-28.md`(ハーネス側圧縮の証拠は
そちらが正本 — 本 doc は常設エージェント固有の観点だけ足す)。

## 1. 設問への直接の答えは文献に存在しない

- **「ハーネスが書く vs エージェントが書く」の同一タスク統制比較は皆無**
  (両調査一致)。最接近が3つ:
  - MemGPT の DMR(2023-10)[ベンダー相当]: 自己編集メモリ 92.5% vs
    再帰要約 32.1%。ただし要約側ベースラインが意図的に弱く、タスクは
    チャット事実想起。「要約は負ける」の根拠には過大評価。
  - Anthropic context management(2025-09)[ベンダー・内部評価非公開]:
    context editing 単独 +29%、+ エージェント自筆 memory tool で +39%。
    差分 ~10pt が「エージェント自筆の上乗せ」の唯一の分解値だが検証不能。
  - SelfCompact(arXiv 2606.23525、2026-06)[統制]: 圧縮の**発火**を
    エージェント自身に決めさせると固定閾値と同等以上・トークン減。
    ただし比較軸は発火主体であり書く主体ではない。
- **プロジェクト状態追跡(進捗・決定・未解決の維持)を測るベンチ自体が
  存在しない**。全ベンチ(DMR/LOCOMO/LongMemEval/MemoryAgentBench)は
  会話事実想起か Web タスク。
- **毎ターン×数十〜数百回の反復領域での品質減衰曲線は未測定**(単発
  崩壊事例と2点比較のみ)。常設エージェントに一番欲しい曲線が無い —
  この空白は dogfood で自分で測るしかない(prior-art doc §5 と同じ結論)。

## 2. 「誰が書くか」より「何をどう書くか」— 形への証拠は収斂している

1. **まるごと再生成は反復に弱い**:
   - ACE の context collapse(arXiv 2510.04618、2025-10)[統制内の事例]:
     蓄積 18,282 トークン・精度 66.7% が**1回の全文書き直しで 122
     トークン・57.1% に崩壊**。増分・構造化更新で回避。
   - openai/codex#14589(2026-03-13、統合時に実在・数値を再確認済み):
     反復 compaction でトークン残存 **13.7% → 6.9%**(**残存率であり
     成功率ではない**点に注意)。ツール結果はセッションの 79.3% を
     占めるが残存 0%。
   - Factory.ai(2025-12)[ベンダー、実運用 36,611 メッセージ]:
     anchored iterative(永続文書への増分マージ)judge 3.70 vs
     全文再生成系 3.35–3.44。
   - Codex CLI は compaction 2回以上で警告し新セッションを推奨(実装
     事実)。Sourcegraph Amp は自動 compaction を廃止(数値なし)。
2. **構造化テンプレートは自由要約と品質同等・トークン −59%**
   (DiscoveryBench 圧縮戦略比較、arXiv 2605.18854、2026-05)[統制]。
3. **無選別の毎ターン書き込みは長期劣化**(arXiv 2505.16067、2025-05)
   [独立・統制]: add-all は固定メモリ比 **−12.05pp**、選別書き込みは
   **+3.42pp**。誤経験の検索は同種の誤りを再生産し複利で蓄積
   (experience-following)。**書き込みの品質ゲートが本体**。
4. **不変部分は要約パイプラインから隔離する**(Governance Decay、
   arXiv 2606.22528、2026-06)[統制・未査読]: 圧縮後にポリシー違反
   0%→平均 30%(制約文が要約から脱落した場合 38%)。制約を圧縮対象から
   外す pinning で 0% に復帰。常設指示(board 運用規約など)は集約の
   たびに消失リスクに晒される。
5. **生ログ保持が精度の王、メモリ方式の価値はコスト**:
   - MemoryAgentBench(ICLR 2026)[査読・独立]: 長文脈ベースラインが
     商用メモリ製品に全勝(正確検索 71.8% vs Mem0 32.6% 等)。
   - Mem0 自身の測定(2025-04)[ベンダー]でも full-context 72.9% が
     全メモリ方式超え。メモリ方式が買うのはトークン >90% 減・
     レイテンシ 90% 減。
   - LongMemEval(ICLR 2025)[査読・独立]: 要約を value にするより
     原文+拡張キー — lossy な一方向圧縮への警告。
6. **機械的削減が生成的要約に先行**(prior-art doc の結論の再確認+新料):
   The Complexity Trap(2025-08)[統制]: masking ≒ 要約をコスト半分で、
   Gemini 2.5 Flash thinking では要約が −9.0pt。AgentDiet(FSE 2026)
   [査読]: 削除のみでトークン −40〜60%・性能維持。CompactionRL
   (2026-07)[統制]: 訓練なしの要約 compaction はモデル・タスク次第で
   益にも害にもなる(Terminal-Bench で 14.6→13.4 に劣化する例)。

## 3. エージェント自己管理側の固有知見

- **書き込み品質はモデル依存の失敗軸**(Letta Leaderboard、2025-05)
  [ベンダー・ハーネスは OSS]: 書きすぎるモデル(不要書き込みの乱発)と
  書かないモデルが実在。常設エージェントのモデル選定と結合する。
  「書き忘れ率」の独立研究は存在しない。
- **記憶の汚染面**(MINJA、arXiv 2503.03704、2025-03)[独立]: クエリ
  経由のみでメモリ汚染、注入成功率 98.2%。board は他エージェント・外部
  由来テキストの流入面であり、「読んだものをそのまま記憶に書く」経路は
  攻撃面になる(2026-01 の追試では正当メモリが十分ある条件で効果減)。
- **手続き的メモリの自己獲得は効く**(AWM、ICML 2025)[査読]:
  エージェントが成功エピソードからワークフローを自分で書いて再利用、
  Mind2Web 相対 +24.6% / WebArena 相対 +51.1%。保存対象が「作業手順」
  なら自己管理の効果は独立ベンチで実証済み。
- **ベンチの信頼性に注意**: LoCoMo は答えキーの 6.4% が誤り・judge が
  誤答の 62.8% を正解判定[監査]。Zep↔Mem0 は相互係争で決着せず
  [双方ベンダー]。モデル/プロンプト固定だけで「アーキ差」の大半が
  消える再測定もある(Continua 2026-04)。ベンダー数値は割り引くこと。

## 4. 判断への含意(数値から言えることだけ)

- 主体の二択を直接支持する数値は無い。実務の収斂は**合成**:
  Anthropic(刈り込み=ハーネス+永続メモリ=エージェント、+39%
  [ベンダー])、Letta sleep-time(ターン間のエージェント整理で同精度
  1/5 コスト、2025-04[ベンダー])。
- どちらが書くにせよ、証拠のある形は同じ: **増分更新(全文再生成しない)
  ・構造化テンプレート・不変部分の pinning・書き込みの選別ゲート・
  生ログは破壊せず参照で辿れる**。
- Horizon の決定済み事項との整合: 決定1(event log 内+送信時投影)は
  「生ログ保持」と完全整合。Tier 2 テンプレート流用は「構造化」と整合、
  brief 原文 pinning は Governance Decay 対策と同型(設計済み)。
  **「毎ターン無条件」の仮説だけが 2-3(無選別書き込みの劣化)と緊張
  する** — 集約の cadence/選別は設計で明示的に扱うべき点。
