# 仕様の整理によって可能になるリファクタリング

第十七巡。`bc108834` のコードと過去の維持判断を照合した。**後方互換性のために残してきた分岐は削除候補に戻せる。中心となるのは provider 設定とツール実行識別の一本化。** その前に、小さく独立した残骸を整理できる。

今回は調査・提案まで。製品コード、保存データ、稼働中のアプリは変更していない。board 固有コード・混在ファイルの board 処理も対象外。以下の機能削除や切替仕様はまだ実装・採用していない。

## 大きな整理の中心

| ID | 一本化する仕様 | 消せる複雑さ／実装上の条件 |
|---|---|---|
| C04 | ファイルの provider 定義を `[[providers]]` に統一する。 | `[provider]` の型・暗黙変換・両形式の優先処理・旧コンストラクタを削除できる。旧コンストラクタの現存呼出しはテスト用。設定例・警告・テストも更新する。設定なしで起動する既定値、環境変数優先、秘密情報を環境変数だけで渡す方式、crate 間の変換責務は残す。 |
| C05 | 公開するツール要求・開始・承認・結果に、実行ごとの `occurrence_id` を必須にする。 | frame・履歴再生・DuckDB の「ID がなければ同じ call ID の直前の要求を探す」という分岐を除去できる。現在の `ToolCallStarted` にも ID がなく、mock 等も省略するため、旧履歴だけ直しても足りない。発行側から統一する。 |
| C06 | 発行されなくなった `TurnEndReason::Halted` と `ApprovalKind::SandboxDenialRetry` を現行契約から削除する。 | 古い列挙値だけのデコード・表示・拒否分岐を除去できる。具体的な停止理由、狭い権限だけを追加して再試行する仕組みは残す。C05 と同じ保存形式・通信の切替単位にまとめる。 |
| C07 | 明示的なモデル切替は最新設定で一度解決し、セッションで反映に成功してから表示を更新する。 | 現在は daemon が最新設定で受理・表示更新した後、セッションが起動時の設定で再解決する。新規 provider を追加すると前者は通り、後者が拒否しうる。二重解決をなくせるが、解決済み設定の受け渡しと成功通知が必要。実行中のターンはそのまま、次のターンから切り替える案。 |

C04 には見落とせない依存がある。**タイトル生成が今も `[provider].base_url` を直接読む。** タイトル生成と自動承認の AI クライアントは OpenAI 互換専用で、最初に作った接続先をプロセス終了まで保持する。新しい既定 provider が Anthropic でも、それをそのまま渡せばよいとは限らない。残す補助 AI の接続先・認証・設定反映時点を揃えてから旧設定を削除する。基本案は OpenAI 互換の名前付き provider を明示的に選び、その解決済み設定にクライアントの寿命を合わせること。**どの provider を補助処理に使うかは未決定。**

C05 でも「provider の一つの呼出し」と「承認・再試行による複数の実行」は別物。再試行待ち、古い非同期完了の拒否、取り消し処理は残る。履歴圧縮も provider call ID を使う別の表現なので、ID 必須化だけで削除できるとは扱わない。

根拠: [設定解決](../../crates/horizon-config/src/lib.rs)、[タイトルの接続先](../../src/agent/session.rs)、[補助クライアント](../../crates/horizon-agent/src/judge/client.rs)、[イベント契約](../../crates/horizon-agent/src/contract.rs)、[frame の照合](../../crates/horizon-agent/src/frame/tool_calls.rs)、[SQL の照合](../../crates/horizon-agent/src/persistence/projection/duckdb/query.rs)、[切替の受理](../../crates/horizon-agentd/src/session/connection.rs)、[切替の適用](../../crates/horizon-agent/src/providers/rig/session/state.rs)。

## 機能を減らすなら整理できる箇所

| ID | やめる機能 | 削除可能な実装と失う価値 |
|---|---|---|
| C08 | 毎入力を複数モデルに提案させて集約する MoA | `[[moa]]` の解決、提案セッションの起動・監視、会話／pass 管理、専用イベント・モデル選択分岐。通常の `task` と子セッション管理は残す。自動の複数モデル比較・集約を失う。利用実態は未確認なので、不要とは判定していない。 |
| C09 | AI によるタイトル整形 | 現在も失敗時に使う最初の入力由来のタイトルに統一し、要約 API 呼出し・専用モデル・接続先・再接続時の試行状態を削除できる。短く整ったタイトルを失う。自動承認の AI は別の機能判断であり、一緒に廃止する理由にはならない。 |

自動承認 AI も廃止すれば判断処理・接続先・非同期判定を減らせるが、その分、人への承認要求が増える。ここは無条件の削除を勧めない。非同期ツール実行や隔離機構まで不要になるわけでもない。

根拠: [MoA pass](../../crates/horizon-agent/src/providers/rig/session/moa.rs)、[提案セッション](../../crates/horizon-agent/src/tools/moa.rs)、[タイトル要約](../../crates/horizon-agent/src/summarize.rs)。

## 実装順と切替条件

1. **C01・C02 を独立して整理。** C03 は旧共有キャッシュ方式への専用支援も終えるなら同時に進める。
2. **C04・C07 を設定の一本化として実施。** 補助 AI の接続先を決め、C09 の採否を反映する。旧 `[provider]` は一度だけ変換し、古い形式を黙って無視して既定値に戻す切替は避ける。MoA を廃止するなら、C08 を先に決めることで、新仕様への移植が不要になる。
3. **C05・C06 をイベント契約の切替として実施。** JSONL の退避と一度限りの変換、DuckDB の再構築、agent wire の版更新、アプリと agentd の再起動までを一単位にする。曖昧な旧実行 ID や bare `Halted` の理由を捏造しない。確実に変換できない履歴は原本を別途保全する。旧 `SandboxDenialRetry` の未決要求を新しい権限付与と解釈しない。

各単位で、正規 CLI 操作、環境変数の優先順位、補助 AI の認証と接続先、reload 後のモデル切替成功／失敗、同じ call ID の再利用・再試行・取り消し・再開、保存→再生→表示の一致を確認する。共通イベント変更で board 側の対応が必要と分かった場合は、その依存を切り分けて調整し、今回の除外範囲を黙って広げない。

## 維持すべきもの・確認範囲

端末の `legacy_bytes` は現在の外部アプリとの通信規約、sandbox の OS 差は実際の権限制御、端末と agent の別 daemon は独立した寿命を守るもの。後方互換性を気にしない方針だけで削除する対象ではない。正本の履歴と圧縮された provider 向け履歴、描画の live／scrollback、timeout と操作の取り消しも、現在の機能・性能・副作用の違いを表す。

なお「DuckDB の遅れを避けるため、resume を JSONL 優先にする」は既に実装済み。現在の loader は通常のイベントを含む `fallback_events` を優先する。再生時の call/result ペア整形まで不要になったわけではない。

確認対象は台帳の維持判断17件と各巡の明示的な維持判断44件。**重複を含む61記録であり、61個の問題ではない。** 各判断の再評価、候補との対応、現在のソース位置・ハッシュ、移行と検証条件は [照合記録](../../scripts/refactor-audit/spec-simplification-review.json) に集約した。以前の調査の台帳は書き換えていない。候補の実利用頻度や削除後の効果量は未測定。C07 の不整合はソース上の経路確認で、今回の実行再現ではない。

調査記録の参照整合性とソース一致を検査し、workspace の既存品質ゲートを実行する。既存テストの成功は現在のコードの健全性を示し、未実装の提案の正しさを保証するものではない。
